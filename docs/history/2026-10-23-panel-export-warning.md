# Ложный Drift При Неготовом SSTP

23 октября2026. Локальная панель4.2.2, без записи на RouterOS/TimeWeb.

## Причина

При неготовом sstp-direct-out RouterOS разбивает terse export: абсолютный путь
раздела, комментарий `# sstp-direct-out not ready`, затем относительная команда
`add`. Старый parser сравнивал эти строки с однострочным export и выдавал
`nakhimova_configuration_drift`. В текущем снимке это затронуло14 правил:
10 filter,3 mangle и1 NAT. Полный нормализованный export оказался побайтно
равен нормализованному baseline, включая порядок. Семантических отличий нет.

## Исправление И Ограничения

`managed.export_lines` соединяет самостоятельный абсолютный путь с последующим
add после исключения комментариев. Параметры и порядок не меняются. Незнакомые
строки не отбрасываются. Baseline exports/hashes не заменялись наблюдаемым
состоянием. Новых исключений для VPN/firewall/маршрутов нет.

Regression проверяет эквивалентность двух форматов и отказ при изменении
action, удалении правила или изменении порядка. Неготовность Direct остаётся
отдельной сетевой проблемой: исправление parser не объявляет тоннель рабочим.
Приёмка с реальных устройств не выполнялась, назначения не переключались.

Исходный config, live export и точный diff сохранены только в закрытом
`.local/backups/nakhimova-drift-20261023/`. Откат: вернуть прежнюю функцию
export_lines и release metadata, перезапустить только локальную facade.
Роутер и VPN-сервисы для отката менять не требуется.
