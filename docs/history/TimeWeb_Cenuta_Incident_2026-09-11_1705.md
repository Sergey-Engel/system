# Отказ Cenuta во время подготовки синхронизации

## Откат мониторинга по запросу пользователя

После первоначальной диагностики пользователь разрешил остановить добавленные
компоненты для проверки влияния мониторинга. Выполнено:

- `vpn-uplink-pilot.service` и `vpn-uplink-exporter.service` остановлены,
  автозапуск обоих отключен.
- Штатный `guardctl.sh ... rollback` удалил 22 принадлежащих manifest правила.
  Состояние: `generation=6`, `status=rolled_back`.
- Снимок перед откатом на TimeWeb:
  `/var/lib/vpn-uplink-guards/pre-rollback.fHWT90m9/`.
- Сравнение JSON до/после: остальные routing rules совпали; все маршруты совпали.
- Контейнер `wg-relay` не перезапускался, продолжает работать.
- Код и история сохранены. Новый синхронизатор не был развернут.
- Панель мониторинга больше не получает свежие серверные измерения; ее старые
  значения не являются проверкой результата отката.
- Восстановление клиентского трафика пока не подтверждено. Требуется тест MacBook.
- Пользователь подтвердил, что Cenuta самостоятельно не перезапускал;
  инициатор наблюдавшегося reboot остается неизвестным.

Ни collector, ни guards автоматически не включать обратно до разбора инцидента.

Время ниже: Europe/Istanbul, UTC+3. Проверка только чтением, без рестартов и изменения маршрутов.

- История collector: Cenuta incident started 16:46:00, confirmed 16:50:00,
  reason `tcp_connect_failed`, инцидент открыт на момент чтения.
- Последний handshake до отказа: 16:43:34.

  Перезагрузку агент в этом шаге не выполнял; инициатор пока неизвестен.

## Проверка изменений

- Попытка deploy_sync остановилась на SSH до получения backup, обновления кода
  и установки LaunchAgent. На сервере history_export.py отсутствует.
- exporter.py mtime 16:22:01; exporter запущен с 16:24:36.
- Collector запущен с 16:41:36; journal подтверждает restart 16:41:32-36,
  ранее зафиксированный при изменении retention на 7 дней.
- Manifest mtime 12:32:21. Это само по себе не доказывает неизменность всех
  runtime rules и не исключает влияние ранее установленного мониторинга.
- Причинная связь отказа с мониторингом не установлена. Работы по синхронизации
  приостановлены; не объявлять отказ доказанной внешней блокировкой.

## Далее

Уточнить инициатора reboot Cenuta, проверить следующую полноценную HTTPS-пробу
и прикладной трафик. При повторении выполнить контролируемое сравнение с временно
остановленным collector отдельно от route guards; не удалять guards общим flush.
