# TimeWeb: локальная история и фоновая подкачка

Статус 2026-09-11: локальный кандидат синхронизатора и API истории реализован;
83 теста прошли, из них 4 новых сценария синхронизации. Развертывание НЕ выполнено:
SSH к `94.241.171.65:22` вернул `No route to host`, локальный forward `19106`
недоступен. Ошибка возникла до резервного копирования и до изменения сервера.
Исторический datasource Grafana еще не реализован: установка Infinity ожидает
разрешения. Серверное хранение ранее сокращено до 7 дней.

## Реализованный кандидат

Мастер: `services/monitoring/timeweb-uplinks/`.

- `collector/uplink_monitor/history_export.py`: консистентные страницы до 100
  циклов (200 строк), UUID базы, неделимые пары Cenuta/Fornex.
- `history_cache.py`: SQLite, атомарное сохранение строк и курсора, проверка
  конфликтующих повторов, UNKNOWN при потере синхронизации. Локальные измерения
  также ограничены семью днями; удаление строк освобождает страницы для повторного
  использования, но не обязано уменьшать размер файла SQLite.
- `sync_daemon.py`: подкачка каждые 30 секунд, backoff до 120 секунд, API на
  `127.0.0.1:19107`; запросы API не запускают сетевые пробы.
- `pilot/deploy_sync.py`: резервная копия через SQLite backup API, обновление
  Python-кода pilot, создание локального LaunchAgent. Пока не завершен успешно.
- Планируемая живая БД: `/Users/sergey/Library/Application Support/timeweb-uplinks/history.sqlite`.
- API: `/api/current`; `/api/history?from=<Unix ms>&to=<Unix ms>&metric=state`.
  Также доступны метрики `success` и `duration`, максимальный диапазон 7 дней.

На последней странице обновляется полный ограниченный snapshot инцидентов,
gaps и текущего состояния. Это передает закрытие уже скачанного инцидента.
Лимит snapshot: 500 KB и не более 6000 записей в каждой таблице; превышение
отклоняет синхронизацию, а не обрезает историю молча. Требует нагрузочной приемки.

Проверено тестами: backfill, повтор без дублей, сохранение истории offline,
UNKNOWN offline, отказ на неполном/измененном пакете, восстановление после
TimeoutError, стабильный UUID и некорректный курсор. Полная приемка disk-full,
смены базы, закрытия инцидента и реальной подкачки после обрыва еще впереди.
Существующий Grafana dashboard пока продолжает читать Prometheus без backfill.

## Пока Mac работает

1. Фоновый LaunchAgent раз в 30 секунд проверяет API через существующий SSH-туннель.
2. Запрашивает только записи после сохраненного курсора; новый batch появляется
   раз в 120 секунд, пустой ответ между проверками является нормой.
3. Проверяет версию схемы, идентификатор базы/поколения и целостность пакета.
4. Записывает пакет в локальную SQLite транзакционно, без дубликатов.
5. Продвигает курсор только вместе с успешным commit; при падении пакет можно повторить.
6. Grafana читает локальный API этой SQLite каждые 10 секунд. Скважность самих
   сетевых измерений от частоты обновления экрана не меняется.

Обычное отставание: длительность серверной пробы + до 30 s подкачки + обновление
экрана. Никаких дополнительных HTTPS-проб на каждый запрос Grafana.

## При переподключении

- Продолжить с сохраненного курсора, загружать ограниченные страницы (например,
  до 500 записей), не всю базу на каждом опросе. Один запрос одновременно.
- Для backfill обрабатывать следующие страницы последовательно с ограничением
  размера/времени запроса. На экране показывать прогресс и время последней синхронизации.
- При потере SSH: экспоненциальный backoff с пределом 120 секунд; локальная история
  остается доступной, текущий статус становится stale/UNKNOWN.
- Если отсутствовали больше 7 дней и сервер уже удалил часть истории: явно показать
  необратимый gap, не заполнять его успешными значениями и не скрывать пробел.

## Контракт данных

Нужен новый paginated export API измерений. Сейчас есть current/summary/incidents,
но нет необходимого incremental raw-history API.

- Курсор относится к завершенному атомарному batch и привязан к идентификатору
  серверной базы. Данные двух upstream нельзя терять на границе страницы.
- Измерения immutable, UPSERT по устойчивому ключу. Проверять дубли и конфликты.
- Инциденты изменяются после восстановления: нужен отдельный revision/cursor
  изменений либо повторное согласованное чтение затронутого диапазона, а не только
  выборка по времени начала. Удаления по retention не должны стирать локальную
  историю неявно; политику локального хранения задать отдельно.
- Сервер сообщает earliest available cursor/time, head cursor и generation.
- Запрос диапазона выполняется из консистентного snapshot, с ограничением памяти,
  размера ответа и времени SQL. Не скачивать открытый файл SQLite простым cp/scp.

Локальная БД: каталог состояния вне Dropbox. Мастер кода/конфигов: System.
Для Grafana понадобится поддерживаемый datasource к локальному read-only API;
новый plugin/пакеты устанавливать только после согласования. Prometheus для
локальных метрик Mac остается без изменений; импорт старых значений в него не нужен.

## Проверки приемки

- Разрыв соединения до commit и после commit: повтор не создает дубликаты.
- Пропуск нескольких часов: после подключения вся доступная история появляется.
- Отсутствие больше retention: явный gap с точными границами доступности.
- Закрытие старого инцидента приходит на Mac даже после загрузки его начала.
- Restart/новая серверная БД, clock rollback, поврежденная страница, disk full:
  не продвигают курсор ошибочно и не создают ложную доступность.
- Графики читают один локальный источник для текущих и исторических данных;
  сравнить суммы/число записей/контрольные хэши с сервером.
