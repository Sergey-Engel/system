# Как сайты и приложения обнаруживают VPN (Механизмы детекции)

Этот файл содержит информацию по методам обнаружения VPN-соединений, включая self-hosted решения (OpenVPN, WireGuard) на базе VPS или домашних серверов.

## 1. Основные методы обнаружения (по приоритету)

### А. Анализ IP по базам репутации (IP Intelligence)
*   **Метод:** Сайты сверяют входящий IP с базами данных (MaxMind, IP2Proxy, IPinfo).
*   **Суть:** Если ASN (номер автономной системы) принадлежит хостинг-провайдеру (AWS, DigitalOcean, Hetzner), IP помечается как «hosting/datacenter».
*   **Вероятность:** 95% для self-hosted VPN на базе VPS.

### Б. Прямая проверка через API ОС (только мобильные приложения)
*   **Метод:** Приложения напрямую опрашивают систему о статусе VPN-интерфейса.
*   **Android:** `NetworkCapabilities.hasTransport(NetworkCapabilities.TRANSPORT_VPN)`.
*   **iOS:** `NEVPNManager.shared().connection.status`.
*   **Суть:** Позволяет со 100% точностью определить наличие туннеля, независимо от «чистоты» IP.

### В. WebRTC-утечки (сайты в браузерах)
*   **Метод:** Браузер через протокол WebRTC выдает реальный локальный или провайдерский IP в обход туннеля.
*   **Суть:** Сайт сравнивает видимый IP соединения и IP, полученный через STUN-сервер.

### Г. Несоответствие системных данных (Fingerprinting)
*   **Геолокация:** Разница между страной IP и часовым поясом/языком системы.
*   **DNS:** Запросы уходят не на те серверы или «утекают» провайдеру.
*   **IPv6:** VPN может не закрывать IPv6-трафик, выдавая реальный адрес.
*   **MTU/MSS:** Характерные размеры пакетов для туннелей (OpenVPN/WireGuard).
*   **TLS Handshake (JA3):** Уникальный «почерк» клиентского ПО.

## 2. Краткие выводы для разных сценариев

| Сценарий | Основной риск | Результат детекции |
| :--- | :--- | :--- |
| **VPN на VPS** | IP-базы (Datacenter ASN) | Обнаруживается почти всегда |
| **VPN дома (Residential)** | API ОС (для приложений) | Обнаруживается приложениями |
| **Браузер (ПК)** | WebRTC + Таймзоны | Виден при отсутствии спец. настроек |

## 3. Рекомендации по минимизации обнаружения

1.  **Для сайтов:** Полное отключение WebRTC в браузере и синхронизация часового пояса с регионом IP.
2.  **Для приложений:** Использование резидентских прокси или системных модулей для скрытия VPN-интерфейса (требуется Root/Jailbreak).
3.  **Сетевой уровень:** Настройка `split-tunneling` и корректное перенаправление DNS внутри туннеля.
4.  **IPv6:** Обязательное отключение или полное туннелирование IPv6.

## 4. Пошаговая инструкция по проверке своего VPN IP

Если ваш IP (например, **5.18.198.112**) находится на хостинге в Нидерландах, пройдите по этим шагам, чтобы увидеть его «глазами» систем безопасности:

1.  **Проверка типа ASN (ipinfo.io)**
    *   Перейдите на [ipinfo.io/5.18.198.112](https://ipinfo.io/5.18.198.112).
    *   Найдите поле **ASN**. Если там указано **"Type: hosting"** (а не "isp"), большинство сервисов (Netflix, ChatGPT, банки) сразу распознают его как VPN/прокси.
2.  **Проверка репутации и скоринга (IPQualityScore)**
    *   Воспользуйтесь [IPQualityScore Proxy Detection](https://www.ipqualityscore.com/free-ip-lookup-proxy-vpn-test).
    *   Введите свой IP. Сервис покажет **Fraud Score** и статус **Proxy/VPN: Yes/No**. Это одна из самых жестких баз, которую используют маркетплейсы.
3.  **Глобальная проверка MaxMind (Первоисточник)**
    *   MaxMind — самая популярная база в мире. Проверьте свой IP через их [GeoIP2 Precision Demo](https://www.maxmind.com/en/geoip2-precision-demo).
    *   Смотрите на поле **User Type**: если там "Hosting" или "Business", IP будет заблокирован многими системами.
4.  **Комплексный тест на анонимность (Whoer.net)**
    *   Зайдите на [Whoer.net](https://whoer.net/) при включенном VPN.
    *   Обратите внимание на показатель **Anonymity**. Если он меньше 100%, сайт подсветит причины (Blacklist, Proxy, разница в Timezone/DNS).
5.  **Проверка утечек (IPLeak.net)**
    *   Зайдите на [IPLeak.net](https://ipleak.net/).
    *   Убедитесь, что в разделе **DNS Address** и **WebRTC Detection** не фигурирует ваш реальный российский IP или DNS провайдера.

## 7. Как решить проблему детектирования "Hosting IP"

Если ваш IP (Fornex) блокируется сервисами из-за его принадлежности к хостингу, есть четыре основных способа "обелить" соединение:

### Способ 1: Резидентские прокси (Residential Proxies) — Самый эффективный
*   **Суть:** Трафик со своего VPN (Fornex) направляется через цепочку прокси, чей IP принадлежит реальному домашнему провайдеру в Нидерландах или другой стране.
*   **Как реализовать:** Использовать сервис (напр. *Asocks, Bright Data, Oxylabs*). В настройках браузера или системы указывается адрес прокси.
*   **Плюс:** 100% прохождение проверок (ASN покажет "ISP", а не "Hosting").
*   **Минус:** Оплата за трафик (обычно от $1-3 за 1 ГБ).

### Способ 2: Резидентский VPS (Residential VPS)
*   **Суть:** Аренда виртуального сервера у провайдеров, которые специально закупают пулы IP у домашних провайдеров (напр. *Starry, DedicatedResidential*).
*   **Как реализовать:** Смена текущего хостинга (Fornex) на такого провайдера.
*   **Плюс:** Можно продолжать использовать безлимитный трафик на высокой скорости.
*   **Минус:** Стоимость таких серверов значительно выше обычных ($20-50 в месяц).

### Способ 3: Мобильные прокси (4G / LTE Proxies)
*   **Суть:** Использование мобильного интернета в качестве выходного узла.
*   **Почему работает:** Мобильные IP выдаются тысячам пользователей одновременно. Сервисы (Netflix, ChatGPT) боятся их блокировать, чтобы не "отрезать" огромное количество реальных клиентов.
*   **Как реализовать:** Покупка доступа к 4G-прокси или подключение к VPN-серверу, на выходе которого стоит 4G-модем.

### Способ 4: Собственное резидентское реле (DIY Residential Relay) — Самый дешевый
*   **Суть:** Установка мини-компьютера (Raspberry Pi или старый роутер) дома у друга/родственника в нужной стране.
*   **Как реализовать:** 
    1. На домашнем устройстве ставится WireGuard.
    2. Ваш текущий Relay (TimeWeb) направляет трафик не на Fornex, а на это домашнее устройство.
*   **Плюс:** Бесплатно (только цена устройства), максимальный уровень доверия.
*   **Минус:** Зависимость от стабильности интернета в "той самой" квартире.

## 8. Оптимизация: Прозрачный Split Tunneling (БЕЗОПАСНЫЙ МЕТОД)

Чтобы не вносить изменения в `table 100` и не рисковать стабильностью системы, используйте метод маркировки пакетов через **ipset**. Это позволит "выдергивать" российский трафик и отправлять его в локальный интернет TimeWeb до того, как он уйдет в туннель NL.

### Шаг 1: Установка IPSet и создание списка
На Relay-сервере (TimeWeb):
```bash
apt install ipset -y
ipset create russia hash:net
```

### Шаг 2: Скрипт автоматического обновления `/opt/wg/update_ru_ipset.sh`
```bash
#!/bin/bash
# Загрузка актуальных списков РФ
curl -s https://antifilter.download/list/russia.lst > /opt/wg/ru_ips.txt

# Очистка и заполнение ipset (безопасно через swap)
ipset create russia_new hash:net
while read -r line; do
    ipset add russia_new $line
done < /opt/wg/ru_ips.txt
ipset swap russia_new russia
ipset destroy russia_new
```

### Шаг 3: Настройка правил маршрутизации (Mangle)
Добавьте эти команды в `PostUp` вашего `wg1.conf` (или `wg0.conf` в секцию интерфейса Relay):

```bash
# 1. Помечать трафик в РФ меткой 1 пакеты от клиентов (10.10.10.0/24)
iptables -t mangle -A PREROUTING -s 10.10.10.0/24 -m set --match-set russia dst -j MARK --set-mark 1

# 2. Направить помеченный трафик в основную таблицу маршрутизации (main)
# Приоритет (pref) должен быть МЕНЬШЕ, чем у правила для table 100
ip rule add fwmark 1 lookup main pref 500

# 3. Включить NAT для выхода через eth0
iptables -t nat -A POSTROUTING -s 10.10.10.0/24 -o eth0 -j MASQUERADE
```

### Как это работает:
1.  Пакет от клиента приходит на сервер.
2.  `iptables` проверяет адрес назначения по базе `ipset russia`.
3.  Если адрес российский — пакет получает метку `1`.
4.  Ядро видит метку `1` и отправляет пакет в таблицу `main` (локальный интернет).
5.  Если метки нет — пакет идет дальше по вашим старым правилам в `table 100` (в Нидерланды).

**Результат:** Ваша `table 100` остается нетронутой, а российский трафик обрабатывается максимально быстро и надежно.
