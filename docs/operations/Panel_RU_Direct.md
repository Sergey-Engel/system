# Российские IPv4 Напрямую: Все Режимы Панели

21 октября 2026. Device routing4.1.0, Direct controller3.1.0.
[Панель](http://127.0.0.1:19118/#site-to-site).

| Режим | Российские IPv4 | Прочий трафик |
| --- | --- | --- |
| WG-Cenuta-RU | Провайдер Нахимова | Прежний WG/Cenuta, с сохранением native local/BitTorrent исключений |
| WG-Fornex-RU | Провайдер Нахимова | Прежний WG/Fornex с теми же исключениями |
| SSTP-Cenuta-RU | Провайдер Нахимова | SSTP до TimeWeb, затем Cenuta, с native исключениями |
| SSTP-Fornex-RU | Провайдер Нахимова | SSTP до TimeWeb, затем Fornex, с native исключениями |

Standard означает прежнюю маршрутизацию площадки. BTH, управление и отдельный
S2S/WireGuard транспорт не переключаются. Новые режимы по-прежнему требуют
явного Apply; Undo и сохранённые назначения не очищаются фоном.

## Фильтрация По IP

Источник - действующий список RU_Networks Нахимова, а не новая сторонняя база.
Поддержаны CIDR и RouterOS диапазоны start-end. После нормализации без расширения
покрытия получено8588 IPv4 CIDR; эквивалентный набор установлен на Фетхие.
Исходный список Нахимова не заменялся и не очищался.

Это фильтрация адреса назначения, не языка страницы, домена, гражданства
владельца сайта или географического местонахождения CDN. Country list не
классифицирует IPv6. Старые Direct IPv6/DNS6 guards сохранены.
Автоматическое обновление списка этим изменением не устанавливается.
Следующая замена набора требует свежего backup, проверки diff и синхронизации
обоих роутеров; не запускать исторические скрипты с remove-before-import.

В четырёх native Split-списках RU exception стоит раньше принудительного
назначения195.133.216.210, который тоже входит в RU_Networks. Это осознанная
смена приоритета: пользователь потребовал направлять все российские адреса
местному провайдеру. Прежние записи force не удалены; теперь они не переопределяют RU.

## Direct Policy

RU/private accept в prerouting останавливает чужие VPN marks. Остальные
направления получают routing-mark Direct таблицы.
Назначения, принадлежащие самому роутеру, исключены из non-RU mark через
`dst-address-type=!local`: доступ к самому роутеру не уводится в Direct.
Старое catch-all source rule больше не должно заново захватывать RU после такого исключения:
оно сужено до1.1.1.1/32 для существующего DNS redirect. Три LAN bypass rules
сохранены. При отсутствии Direct default его blackhole остаётся закрытым
выходом для non-RU, без автоматического перехода на WAN.

До leak guard добавлены exact MAC/IP RU-out accept только в ether1 и
established/related RU-in accept только из ether1. Входящие новые подключения
не разрешаются. Эти потоки не попадают в FastTrack. DNS redirect исключает
назначения RU_Networks: запрос к российскому DNS не переписывается на1.1.1.1.
Остальные DNS запросы сохраняют прежний redirect и идут через Direct.

Контроллер строго проверяет порядок RU/private/mark, положение RU accept до
leak и поля всех owned rules. Неизвестный drift блокирует новую запись.
Новые specs включаются только после ru_bypass_enabled в проверенной миграции.

## Безопасное Сопровождение

Сравнивать экспорты с одинаковым режимом скрытия секретов. Sensitive и redacted
нельзя сравнивать как одинаковые вне scope. Данные различий сохранять приватно.
Не считать Safe Mode самостоятельным доказательством полного отката: новые
firewall match fields могут остаться после undo. Повторно сверить export;
только доказанные изменённые правила можно восстановить из pre-export в тех
же позициях. Empty selector не равен отсутствующему свойству для строгого readback.

Большой новый country list сначала подготавливается без активных consumers
вне Safe Mode:8588 записей превышают undo budget. После проверки полного
равенства покрытия выполняется короткая активация под shared lock/Safe Mode.
При ошибке удаляется только собственный новый набор с точным comment/list,
исходный список не затрагивается. Нельзя восстанавливать весь router backup
или перезапускать TimeWeb/WireGuard ради такого изменения.

Пробы локально порождённых пакетов измеряют egress в postrouting: RouterOS
выполняет output routing adjustment после output filter. Ранний output counter
может показывать старый маршрут и не является проверкой окончательного выхода.
Изолированная проба не равна браузерной приёмке настоящего клиента.

## Границы Проверок

С роутеров проверены пять режимов Нахимова и Direct Фетхие: российский IP
через местный WAN, зарубежный через нужный интерфейс; DF1200 и счётчики
postrouting. При потере только тестового маршрута RU остаётся доступным,
non-RU блокируется. Рабочие пользовательские тоннели для этого не отключались.

С реальных устройств после этой RU-миграции пока не проверены вход через
LAN/Wi-Fi, MAC-привязка, DNS redirect, HTTPS и приложения, а также поведение
при настоящем обрыве тоннеля. Ранее подтверждённый пользователем Direct
выход MacBook не заменяет новую приёмку всех режимов с -RU.
IPv6 country routing, полный reboot и длительная нагрузка в этот scope не входят.
