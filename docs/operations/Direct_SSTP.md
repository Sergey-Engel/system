# Прямой SSTP: Эксплуатация

Статус: постоянный канал и локальное управление установлены, 19 октября 2026.
Контроллер 3.0.0: единое взаимоисключающее управление маршрутами устройств.
История до 3.0: независимые списки обоих направлений Direct. Обратный выход
Нахимова → Фетхие установлен; проверен с роутера, но не с реального клиента:
[протокол обратного направления](../history/2026-10-19-sstp-reverse-egress.md).
Проверочные Direct-назначения сняты; прежние Split-назначения сохранены.
Протокол первоначальной установки:
[приемка и ограничения](../history/2026-10-19-sstp-direct-permanent.md).

## Схема

Нахимова `sstp-direct-out` -> Интернет TCP443 -> Deco -> Фетхие
`192.168.68.117:5443`, `sstp-direct-in`. Адреса внутри канала:
Фетхие `10.60.64.1`, Нахимова `10.60.64.2`, MTU1400.
Mutual TLS1.2, AES256-GCM, PFS, отдельный PPP secret и CA. Прежний WG/IPIP
через TimeWeb не является внутренним транспортом SSTP и не переключается.

## Панель

Локальная [VPN-панель](http://127.0.0.1:19118/#site-to-site), вкладка
Device routing. VPN-раздел передается из прежней серверной панели через отдельный
SSH-forward19119. Серверные файлы/службы и его sandbox не меняются.
Новая facade слушает только127.0.0.1:19118. `timeweb-vpn` открывает ее;
`timeweb-vpn status`, `stop`, `logs` относятся к двум новым локальным агентам,
а не к VPN-транспорту. Остановка панели не останавливает SSTP или выбранные
устройства. Агенты стартуют после входа в macOS, RouterOS работает без Mac.

Выберите площадку: Nakhimova первая и открывается по умолчанию, затем Fethiye.
На Нахимова видны только enabled permanent DHCP reservations `defconf`,
включая offline. Режимы Standard / Split Cenuta / Split Fornex /
Direct SSTP via Fethiye. На Фетхие видны только авторизованные Wi-Fi
registrations MikroTik. Режимы Standard / Direct SSTP via Nakhimova.
DHCP-запись сама по себе, Ethernet-клиент или устройство Deco не попадают
в список Фетхие. Без однозначной DHCP MAC/IP-привязки строка read-only.

Строка содержит имя из справочника и IP, текущий режим и меню нового режима.
Выбор применяется только кнопкой с галочкой справа. Standard исключает
устройство из обоих Split-списков и выключает его Direct-политику. Один
контроллер не допускает одновременного включения в разные режимы.
Split сохраняет существующие RU/local/BitTorrent исключения и не означает
полный VPN всего трафика. Standard означает прежние общие правила площадки,
а не обход всех её глобальных политик. Ни одно устройство при установке UI
не переключалось. Назначения вне eligibility сохраняются и показываются
счётчиком, без автоматической очистки. Сообщения разделены по площадкам.

Исторические статусы Direct read API:
Статус remote означает проверенные конфигурацию
и маршрут, а не доказанный HTTPS-запрос конкретного устройства. Blocked:
выбор сохранен, тоннель недоступен, местный Internet не используется.
Unknown: проверка не завершена/недоступна, последнее выделение сохраняется.
Pending: операция не подтверждена; пока guards не установлены, местный
Internet еще возможен. Нельзя трактовать Pending как принятый Remote.

После ошибки Apply ответ перечитывает сохраненный state, а не использует
незавершенные изменения в памяти. Pending-устройство видно при сохранении
eligibility; разрешён только явный возврат того же MAC/IP/lease в Standard.
Отключённый Wi-Fi-клиент Фетхие не теряет назначение; восстановление в UI
возможно после повторного подключения, либо отдельной reviewed операцией.
Отключенные правила сами по себе не подтверждают завершение всех шагов.
Очистка tracked flows не повторяет запись: после RuntimeError проверяется
существование точного ID; уже исчезнувший flow считается очищенным. Если ID
остался или проверка недоступна, ошибка/pending сохраняются. Диагностика
`last-error.json` включает phase, без вывода конфигурации и секретов.

Вкладка не обновляется по таймеру. Состояние читается при открытии вкладки,
по кнопке обновления справа от заголовка и после команды Apply.
Время рядом со статусом показывает момент последней проверки, не live-мониторинг.
Ошибка команды остается до закрытия крестиком или новой команды;
ручное обновление статуса ее не скрывает. Ошибка смены записи устройства
означает отказ до изменения настроек: обновить список и повторить выбор.
Проверка привязана к MAC/IP/DHCP-записи выбранного устройства, версии
сохраненного выбора и конфигурации; изменения других DHCP-клиентов не мешают.

Данные SSTP идут напрямую, но SSH-проверка конфигурации Нахимова использует
прежний management proxy через TimeWeb. Временная недоступность управления
не доказывает обрыв SSTP. Начальное SSH-соединение при транспортном отказе
повторяется один раз; ключ, авторизация, serial и конфигурация проверяются
без ослабления. Команды записи не повторяются. Если управление по-прежнему
недоступно, новый Direct блокируется, сохраненный выбор не меняется. Standard
остается возможен при подтвержденной конфигурации исходного роутера. Таким образом,
новый выбор в панели пока зависит от доступности прежнего management path;
это не независимое от TimeWeb управление прямым каналом.

Статическая DHCP-аренда сохраняется после возврата Standard; DNS/gateway аренды не
меняются. Частный MAC другой Wi-Fi-сети является другой identity. После
смены MAC необходимо выбрать новую запись; автоматического переноса по
имени нет. Смена режима прерывает только tracked flows выбранного IP,
чтобы старый FastTrack/NAT не сохранял прежний выход.

## Защита И Изоляция

Fethiye lookup-only table `sstp_direct`: прямой default и резервный blackhole,
без fallback в main/TimeWeb. Source-specific rules включаются последними.
Новые source/MAC guards, перехват DNS TCP/UDP53 на1.1.1.1 через выбранный
маршрут и блок IPv6 для выбранного MAC исключают обычный local egress.
Локальные подсети68/88/89 сохраняют существующие маршруты; новый SSTP не
открывает новые LAN-to-LAN возможности. DNS-кэш устройства и VPN-приложения
не считаются частью проверки обычного egress.

Новые фильтры до FastTrack принимают только разрешенные потоки SSTP.
SNAT на Фетхие в10.60.64.1 и scoped masquerade Нахимова исключают изменения
старой return policy. Внешний listener требует клиентский сертификат и PPP
secret; IP источника не закреплен, чтобы смена NAT Нахимова не обрывала канал.
Это не разрешение публичного SSH/WebFig. Управление Нахимова использует
прежний strict SSH proxy, без правок TimeWeb.

## Обратное Направление

Тот же SSTP постоянно переносит оба направления. Нового соединения, проброса
Deco, сертификатов и PPP-identity не создаётся. На Нахимова новая таблица
`sstp_fethiye` содержит default через `sstp-direct-out` и blackhole254.
Выбор включает отдельные MAC/IP guards, DNS TCP/UDP53, IPv6 block и
source-specific lookup-only rule. Узкий `prerouting accept` для выбранного
клиента останавливает прежние VPN marks до применения новых routing rules.
Guard закрывает публичный трафик через любой выход кроме SSTP, не только WAN.

Нахимова SNAT переводит только публичные назначения выбранного маршрута из
`.88/24` в `10.60.64.2`. Для private destinations SNAT не применяется, чтобы
не расширять существующий доступ к management адресу роутера Фетхие.
Фетхие принимает scoped Internet flows `.64.2` из SSTP только в `ether1`,
masquerade; reply разрешён только established/related. Нового LAN-to-LAN
доступа нет; существующие маршруты локальных сетей сохраняются.

Прямой и обратный контроллеры используют один lock и общие строго сверяемые
baseline, но разные state/generation/audit. Reverse state:
`.local/config/sstp-direct/reverse/state.json`; HTTP read `/s2s-reverse-state`,
legacy write `/s2s-reverse-action` закрыт (410), как и `/s2s-action`.
Все записи идут через `/routing-action`; GET `/routing-state/nakhimova` и
`/routing-state/fethiye` возвращают unified список. Старые Direct reads сохранены.
Shared journal `.local/config/sstp-direct/routing-state.json` фиксирует
intent/phase до первой записи. Unknown acknowledgement не повторяет запись.
Baseline обновляется только по exact reviewed diff выбранного host membership;
shared CIDR/dynamic/чужой drift блокирует запись. Старый CLI Direct также
отказывает при `routing_enabled=true`.
Одинаковый MAC в другом направлении не переносит право выбора/revision.
Server-side status показывает readiness, не клиентскую приёмку и не скорость.

При недоступности управления Нахимова нельзя ни добавить, ни удалить его
клиента: исходный роутер должен быть проверен перед записью. Остановка панели
не отменяет сохранённые политики. Транспорт переподключается штатным SSTP
client; автоматического переключения между SSTP и TimeWeb нет.

Router-originated HTTPS и DF1400 прошли; при отключении только reverse default
включался blackhole, HTTPS переставал работать, после enable восстанавливался.
Общий SSTP в ходе отрицательной проверки оставался up. `/tool fetch` запрещён
существующим device-mode Нахимова: ограничение не ослаблялось, внешний IP
клиента этим тестом не доказан. DNS/FastTrack/MAC физического клиента также
не принимались без реального клиентского теста. См. протокол для точной границы.

Основание: [RouterOS policy routing](https://help.mikrotik.com/docs/spaces/ROS/pages/59965508/Policy+Routing),
[FastTrack и conntrack](https://help.mikrotik.com/docs/spaces/ROS/pages/130220087/Connection+tracking).

## Имена По MAC

Unified UI использует только exact full-MAC
[LAN inventory](../../config/inventory/lan-devices.json); без binding выводится
`Unknown device`. DHCP hostname и vendor lookup не подменяют имя справочника.
MAC доступен в подсказке строки. Семь имён Нахимова перенесены из существующих
явных названий permanent reservations с [provenance](../history/2026-10-19-unified-device-routing.md).
Это не атрибуция модели/владельца по производителю.

Ниже описан fallback старого read-only Direct API, не unified UI:

Для locally administered/private MAC база производителей не используется.
Без точного подтвержденного binding выводится `Unknown device (private MAC)`.
Не объединять private MAC разных SSID по имени, IP или производителю.
Подпись не влияет на MAC/IP selection, revision, разрешения или маршрутизацию.
Ошибки баз имен не блокируют транспорт и не подменяют его status error.

IEEE MA-L/MA-M/MA-S/IAB snapshot: `.local/cache/mac-vendors.json`. Runtime
lookup полностью локальный, без передачи адресов стороннему сервису.
Cache старше90 дней отмечается stale в `name_lookup`, не обновляется таймером.
Ручное обновление snapshot (вне status/Add, HTTPS verification включена):

```sh
.venv/bin/python -B services/transport/site-to-site/direct_names.py --refresh
```

При ошибке загрузки сохраняется прежний snapshot. Неоднозначный префикс
не дает производителя и блокирует fallback к более короткому префиксу.
Источник: [публичные списки IEEE](https://standards.ieee.org/products-programs/regauth/).
Cache восстанавливаемый и не относится к credential store. Старые VPN
inventory и выданные профили при изменении подписи не меняются.

## Постоянство И Обслуживание

Client enabled, add-default-route=no, keepalive10s; RouterOS сохраняет эти
параметры и переподключается независимо от панели и количества клиентов.
Физический reboot не проводится в этой задаче, поэтому фактическая загрузка
после потери питания отдельно не принимается за проверенную.

CA/leaf действуют825 дней. Панель предупреждает за30 дней. Endpoint закреплен
в SAN по текущему публичному IPv4 Фетхие: смена адреса требует reviewed
перевыпуска server certificate и изменения connect-to. Автоматически
доверять новому IP или отключать проверки сертификата запрещено. Это не
автоматическая DDNS/renewal-система. Deco DHCP reservation сохраняет `.117`.

Если табличный `print as-value` не содержит certificate fingerprint, читать
его явным `get <id> fingerprint`. Отсутствующее поле не считать несовпадением
и не исправлять переимпортом сертификата. Сверить фактический отпечаток
с сохранённой PKI, остановиться при реальном различии.

## Источники И Откат

Код `services/transport/site-to-site/device_routing.py`, `routing_panel.py`,
`direct_*.py`, `sstp_direct.py`.
Приватные config/state/audit: `.local/config/sstp-direct/`, каталоги700,
файлы600; ключи остаются в существующей `.local/ssh/`. PKI, passwords,
полные exports и backup evidence только `.local/backups/site-to-site/`
и canonical `.local/secrets.json`. Локальные LaunchAgents имеют собственные
labels `com.sergey.sstp-panel` и `com.sergey.sstp-panel-forward`.

Откат установки: сначала подтвержденный Remove всех выбранных устройств,
затем exact namespace `s2s-sstp-direct-v1`, table `sstp_direct`, восстановление
сохраненных global SSTP server settings и удаление только новых fingerprint
certificates. Не удалять state или UI вместо возврата Local. Не выполнять
flush, reboot, broad restore или изменение WG/IPIP/TimeWeb. После отката
сверить exports вне собственного scope, сертификаты и старые LAN paths.
