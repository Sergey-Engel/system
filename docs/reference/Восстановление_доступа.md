## План восстановления нормального доступа к Cenuta

1. Сохранить временный `known_hosts_cenuta_temp` до получения подтверждения.
2. Получить от Cenuta подтверждение текущего host key либо выполнить проверку
   через рабочий web-terminal.
3. После подтверждения перенести доверенный ключ в постоянную отдельную запись
   Cenuta или аккуратно обновить запись в `.local/ssh/known_hosts`.
4. Выполнить read-only аудит: hostname, IP, маршруты, `wg-cenuta`, handshake,
   `nftables`, forwarding и конфигурационные файлы.
5. Сверить фактическую конфигурацию с [Cenuta_Parameters](<../hosts/cenuta/Cenuta_Parameters.md>) и
   [MikroTik_Quick_Guide](<../quick-start.md>).
6. Только после фиксации состояния решить, нужен ли перезапуск WireGuard,
   обновление Ubuntu или восстановление peer-соединения с TimeWeb.

До завершения шагов 1-4 не выполнять `ssh-keygen -R`, не принимать ключ без
проверки, не переустанавливать VPS и не менять WireGuard-конфигурацию.
