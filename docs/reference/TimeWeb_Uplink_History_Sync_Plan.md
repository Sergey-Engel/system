## Контракт локального master

Master: [collector](<../../services/monitoring/timeweb-uplinks/collector/README.md>).
Код читается статически; серверная идентичность этой версии не проверена.

1. `history_export.py`: серверный `/api/sync?after=<slot>&limit=<cycles>`.
   Один snapshot SQLite на страницу; максимум **100 циклов / 200 строк**,
   неделимые пары Cenuta/Fornex. Это не прежние предполагаемые 500 записей.
2. Курсор представляет slot, источник имеет постоянный `database_id` UUID.
   Пакет содержит `version=1`, `interval=120`, `after/next/head/earliest`;
   строки пары согласованы по run/generation/revision.
3. Экспорт строк ограничен 400 000 байт. На последней странице передается
   полный snapshot `channels/incidents/gaps`: до 6000 записей на таблицу
   и до 500 000 байт. Превышение дает ошибку, не молчаливое усечение.
4. `history_cache.py`: samples и cursor сохраняются одной транзакцией.
   Совпавший повтор не дублируется, измененный повтор отвергается.
   Разные серверные базы разделены по UUID.
5. `sync_daemon.py`: последовательно читает через существующий forward
   `127.0.0.1:19106`; HTTP timeout 5 s, ответ до 1 000 000 байт.
   Один проход ограничен 16 страницами и проверкой бюджета 20 s между страницами.
   Это не жесткий end-to-end deadline: текущий запрос может завершиться позже.
6. После полного прохода пауза **30 s**, при незавершенном backfill **1 s**.
   На ошибках задержки **30 / 60 / 120 s**. Это не частота серверных измерений.
   Отдельный backoff daemon TimeWeb может достигать 600 s.
7. Локальная SQLite по deploy-кандидату:
   `~/Library/Application Support/timeweb-uplinks/history.sqlite`, вне Dropbox.
   Локальный API слушает `127.0.0.1:19107`; чтение API не запускает сетевые пробы.

Инкрементальный raw-history API уже существует в master. Формулировка
«нужно реализовать API, его еще нет» устарела. Наличие кода не подтверждает,
что этот endpoint когда-либо работал в установленной копии.

## Текущее состояние и offline

`/api/current` показывает source UUID, cursor/head, время синхронизации,
готовность источника, current, incidents, gaps и missing.

Текущий статус считается свежим только при всех условиях:

- нет ошибки синхронизации;
- полная последняя страница получена не более **75 s** назад;
- cursor достиг head, `source_ready=true`;
- возраст серверного наблюдения от 0 до **180 s**.

При потере синхронизации текущие каналы становятся UNKNOWN, старые
измерения остаются историей. Догруженные точки не являются свежими probe.
Закрытие ранее скачанного инцидента передается новым финальным metadata snapshot,
а не только новыми строками с более поздним slot.

`/api/history?from=<Unix ms>&to=<Unix ms>&metric=state` поддерживает также
`success` и `duration`, диапазон до **7 дней**.
Отсутствующие слоты возвращаются как `null`, записанные UNKNOWN как код 0.
Исторический API показывает только активный UUID источника; это не единый
график всех прежних серверных баз. Интерфейс выбора прежней базы не реализован.

## Retention и пробелы

Серверная политика pilot master: **7 дней**, prune после цикла.
Остановленный collector не очищает и не дополняет историю.
Локальный cache удаляет samples старше 7 дней только при успешном apply;
отдельной offline-очистки нет. Таблицы sources/missing не имеют той же
политики удаления. Нельзя обещать hard limit возраста или размера всей БД.

Если после прежнего cursor серверный earliest перескочил доступные слоты,
cache записывает missing. При первом подключении без cursor неизвестная
предыстория не восстанавливается. Точные границы gap и отображение gaps
на графике еще требуют приемки. Ни 7-дневный лимит API, ни retention не
доказывают семь суток непрерывных наблюдений.

SQLite освобождает страницы для повторного использования; файл не обязан
уменьшаться. Живой WAL-файл нельзя переносить обычным копированием.
Нужен согласованный SQLite backup, не чтение открытой БД через Dropbox.

## Grafana и deployment

Текущий provisioned dashboard пилота читает Prometheus. Он не использует
cache API и не заполняет пропуски автоматически.
Infinity datasource для этого пути не реализован/не подтвержден как развернутый.
Подключение API, версия plugin и установка требуют отдельного решения.

`pilot/deploy_sync.py` является изменяющим инструментом: делает backup,
вызывает updater серверного pilot и создает/загружает Mac LaunchAgent.
Он не является read-only проверкой и не запускался в ревью.
Нельзя повторять его вслепую при выключенных сервисах.

Историческая синтетика 2026-09-11: 720 batches / 1440 строк в сутки,
10 080 строк / 4 915 200 байт за 7 суток; резерв 50 MiB только расчетный.
Свободный диск и RAM из того замера не являются текущими значениями.

## Открытая приемка

- Проверить deployed API/version/hashes, существование cache и LaunchAgent,
  работоспособность порта 19107 с учетом returncode/stderr.
- Backfill нескольких часов, повтор после разрыва до/после commit,
  отсутствие дубликатов и ложного UP.
- Пропуск дольше retention, первый импорт без предыстории,
  закрытие старого инцидента, границы диапазонов и null/UNKNOWN.
- Смена UUID, новая пустая БД, clock rollback, поврежденная страница,
  disk-full/locked DB; cursor не должен продвигаться ошибочно.
- Максимальный metadata snapshot и backlog под нагрузкой,
  явная ошибка при превышении лимитов.
- Сопоставить строки, timestamps и контрольные суммы cache с сервером;
  затем проверить Grafana из ее контейнера, старый Mac dashboard не заменять.
- Согласовать backup/restore и политику очистки всех локальных таблиц.

Четыре теста `test_history_sync.py` подтверждают наличие сценариев
idempotent backfill/offline, неполных/измененных batch, transport failure
и UUID/invalid cursor. Чтение тестов не равно их новому успешному запуску.
В этом ревью тесты, deployment и сетевые запросы не выполнялись.
