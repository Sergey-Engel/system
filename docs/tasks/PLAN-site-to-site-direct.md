Новый кандидат `wg-forward-trial`, owner `s2s-forward-trial-20261018`:
Нахимова `10.60.62.1/30`, UDP51971 инициирует соединение к свежему публичному
адресу Фетхие UDP51972; Фетхие `10.60.62.2/30` отвечает через сохранённый проброс.
Диапазон и порты должны быть свободны live. Endpoint Нахимова на ответчике не
задан: переведённый порт изучается из аутентифицированных пакетов.

Только новый интерфейс, адрес, peer и пять точных фильтров на каждой площадке.
Внешний UDP разрешён только от публичного IP другой площадки; внутренний input
разрешает только ICMP двух тестовых адресов, forward запрещён. Старые WG peers,
маршруты LAN/Internet, NAT, DNS, клиенты и TimeWeb не меняются. Старый one-shot
оператор Oct17 не запускается: новый writer использует лишь проверенные
низкоуровневые helpers. Safe Mode на обоих роутерах без takeover, таймер300s,
undo Ctrl+D, затем точное сравнение baseline. Не применять scheduler/device-mode.

Критерий транспортного теста: восемь серий двустороннего ICMP, семь последних
без потерь, рост RX, endpoints только площадок, затем DF1380. Это проверка
router transport, не приёмка приложений, постоянного мониторинга или failover.
Любой результат завершается удалением кандидата. Настройка Deco, сделанная
владельцем, не удаляется. Проверки по расписанию остаются на паузе.

## Границы

- Новые независимые WG identities, интерфейс `wg-direct-trial`, UDP 51971/51972,
  адреса `10.60.62.1/30` и `.2/30` только после проверки свободного диапазона.
- Второй ограниченный кандидат: новый peer только `.62` на существующем
  `wg-s2s-tw`, с внешними endpoints уже поддерживаемых UDP mappings. Старые
  interfaces/peers/AllowedIPs не редактируются. Тестовые source/destination
  `.62/30` явно запрещены в forward; остальной действующий трафик не затронут.
  Общий WG socket не означает relay: peer endpoint указывает на другую
  площадку, а не TimeWeb; hub не имеет AllowedIPs/маршрута для `.62/30`.
- TimeWeb используется для наблюдения внешних UDP endpoints существующим
  packet capture, не для пересылки данных прямого эксперимента. Его firewall,
  WG config и сервисы не изменяются.
- На новом интерфейсе разрешён лишь ICMP между двумя тестовыми адресами;
  остальной input и весь forward через него явно запрещены.
- Не меняются LAN routes, default routes, NAT, существующие WG peers,
  пользовательские устройства, DNS, IPv6, Deco, пакеты и службы.
- Перед записью: verified backups двух роутеров, точный baseline, identity.
- Первый способ автоудаления через scheduler отклонён device-mode Нахимова
  до создания WG/filter объектов. Защиту не ослаблять. Альтернатива для теста:
  штатный Safe Mode с подтверждением захвата без takeover, менее 100 операций,
  ограничением рабочего процесса 300 s и Ctrl+D для полного undo. При потере
  управления действует встроенный Safe Mode rollback (TCP timeout не мгновенный).
  Затем точный cleanup только объектов текущего owner и сравнение exports.
- Не оставлять эксперимент как постоянный/принятый туннель. Если транспорт
  успешен, постоянная интеграция требует отдельного guarded changeset,
  мониторинга, восстановления endpoint и автоматических packet-level тестов.
- Отсутствие handshake не доказывает конкретный тип NAT или блокировку ISP.
- SSH из WAN не открывается; timer проверок доступности остаётся на паузе.

## Критерии

Прямой transport PASS требует свежего взаимного handshake, двустороннего
ICMP с привязкой к новому интерфейсу, MTU test и внешних endpoints площадок,
не TimeWeb. Обязателен контроль старого пути и полное восстановление baseline.
Если тест не проходит, результат Failed/Blocked, а не скрытый fallback через
TimeWeb. Подтверждение клиентского приложения не подменяется router ping.
